# Deletion Criteria (PhotoCraft)

This document fixes the range in which I (the agent) may delete files under `D:\USERFILES\GitHub\photocraft`.
**I do not widen that range by my own judgement.** Anything not named here is not deleted, not one byte.

---

## Section 0 (highest, overrides everything else)

`target\release\photocraft.exe` and `target\release\photocraft.pdb` are **never deleted.**

- There is no exception: not the owner's instruction, not a build's convenience, not a shortage of space, not tidying, not a line in this or any other document, not my own judgement.
- No other section of this document, no other document, and no precedent changes this section.
- These two files are in neither list: not among "what may be deleted", and not among "what an exception may delete". They sit outside both.
- **Having followed a procedure is never a reason to delete.** A deletion that breaks this section is a violation even when every step was carried out correctly.

---

## Section 1 (checks that come before any deletion)

Before a deletion command runs, all four must hold. If any one fails, nothing is deleted.

1. **The target is a row of the table in Section 3.** A target that is not in the table is not deleted. The range is never widened by a similar name, a parent directory or a wildcard.
2. **The target's paths were listed one by one.** A `-Recurse` is allowed only when its root is exactly a row of that table.
3. **The list of targets contains neither `target\release\photocraft.exe` nor `target\release\photocraft.pdb`.** If either appears, that deletion is abandoned.
4. **The SHA-256 of `target\release\photocraft.exe` was measured and recorded.**

## Section 2 (checks that come after any deletion)

1. Measure the SHA-256 of `target\release\photocraft.exe` again and compare it with the value recorded in Section 1.4. **If they differ, report it at once and stop all further work.**
2. Measure the bytes freed and the free space on `D:`.
3. Measure `git status --short` and confirm the working tree was not touched.
4. Report the files that remain, and name every file that was left alone with the reason it was left.

## Section 3 (what may be deleted — nothing else is)

| Target (exact) | What it is |
|---|---|
| `target\debug\` | the debug build tree (regenerated by the next debug build) |
| `target\tmp\` | the build's scratch area |
| `target\release\deps\` | the release build's dependency artefacts (regenerated) |
| `target\release\build\` | build-script output |
| `target\release\.fingerprint\` | build fingerprints |
| `target\release\incremental\` | incremental build intermediates |
| `target\release\examples\` | example build output |
| `target\.rustc_info.json` | cargo's cache record |
| A scratch file directly under `target\` that this session made | `*.ps1` (one-off scripts), `*.log` / `*.log.err`, `*.graphql`, temporary `*.json`, verification `*.png`, temporary `*.rs` / `*.md` / `*.tsv`, `newpin.txt` and the like |

When it is unclear whether a file was made by this session, **it is not deleted**. Its name and the reason go in the report.

## Section 4 (command shapes that are never used)

These widen the range even when every path they touch is in Section 3, so they are not used.

- `Remove-Item -Recurse -Force` on `target`, `target\`, `target\release`, `target\release\*` — a parent, the whole tree, or a wildcard.
- `git clean -xfd` / `git clean -fd` — untracked files deleted in one sweep.
- `rm -rf` at `target`'s parent or above.
- A path held in a variable and passed to a deletion without checking its value.

## Section 5 (past violations)

| Violation | What happened |
|---|---|
| Deleting a shipped executable | `target\release\photocraft.exe` was deleted (2026-11-18; the file the owner tests with) |
| Deciding the range alone | "Unnecessary" was defined narrowly by me and `target\debug` (116.7 GB) was left (2026-11-19) |
| Keeping caches for convenience | Rebuild time was weighed and the caches were kept |
| A false completion report | 8.4 MB was deleted and reported as "deleted" |
| Wording that shields a procedure | "exe and pdb are not an exception" was written, which left a hole that could justify deleting them (2026-11-20) |

## Section 6 (how this document is used)

- This document sets an **upper bound** on deletion. It is never a reason to delete something.
- I do not rewrite the table in Section 3. When it has to change, the owner's explicit word comes first, and then only that one row changes.
- When this document and the owner's instruction disagree, the outcome **favours not deleting**.
